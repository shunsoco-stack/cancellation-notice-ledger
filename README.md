# 解約通知期限帳

## 概要

個人・小さな事務所の自動更新契約について、**解約の申し出期限**を逆算する台帳です。
今月・来月に間に合う手続き、今回間に合わない契約と次の機会、止めた場合の節約見込みを確認できます。

## 主な機能

1. **契約と更新周期・通知期間の登録**
   - サブスク、リース・レンタル、保守・サポート契約、通信・回線、会員・その他に対応。
   - 名称・提供元・料金・支払周期・開始日・初回期間・更新期間・4種類の期限ルール・申し出方法・担当者・メモ・状態を登録、編集、削除。
   - フォームで次回満了日、申し出期限、残り日数を即時プレビュー。
2. **解約通知期限の自動計算**
   - 今日以降で最初の満了日と申し出期限を計算し、期限切れ／7日以内／今月中／来月／それ以降／申し出済み／解約済みに分類。
   - 期限を過ぎた場合は、次に間に合う満了日・申し出期限を表示。
   - 詳細画面のタイムラインで、開始日から期限までの計算過程を確認。
3. **今月・来月の手続きリスト**
   - 「解約する／継続する」の判断を保存し、申し出方法の確認、申し出日、受付確認、返却をチェック。
   - 期限内に申し出たかを判定。手続き完了後は対象の満了日で解約済み。
   - 年額の節約見込み・継続中の年額合計、12か月の申し出期限年表、BOM付きCSVダウンロード。

## 計算ルール

### 暦日と満了日

- 今日の基準は日本時間（Asia/Tokyo）。日付は `YYYY-MM-DD` で保存します。
- localStorageの読み込みと「今日」の決定はクライアントのマウント後に行います。
- 開いたままの場合も1分ごとに日本時間の日付を確認します。
- **満了日＝開始日に契約期間を足した日の前日**です。
  例：2025-04-01開始・12か月 → 2026-03-31満了。
- 更新後の満了日は、開始日に「初回期間＋更新期間×更新回数」を足した日の前日です。
  今日以降で最初の満了日を今回の満了日とします。満了当日は今回に含みます。
- 同日がない月は月末に補正します。1/31＋1か月は2/28（うるう年は2/29）。
  満了日はそのさらに前日です。毎回開始日から加算し、補正によるずれを累積させません。
- 初回・更新期間は1〜120か月。開始日は1900〜2200年の暦日を扱います。

### 申し出期限

| ルール                         | 計算                                           |
| ------------------------------ | ---------------------------------------------- |
| 満了のNか月前の同日まで        | 満了日からNか月を引く。同日がなければその月末  |
| 満了のN日前まで                | 満了日からN暦日を引く                          |
| 満了月のNか月前の月末まで      | 満了月からNか月戻った月の末日                  |
| 次回更新日（請求日）の前日まで | 更新日を満了日の翌日と定義し、その前日＝満了日 |

Nは日数の場合1〜3650、月数の場合1〜120です。
期限当日（残り0日）は間に合う日として扱い、翌日から期限切れです。
期限切れの場合は更新周期を進め、申し出期限が今日以降になる最初の機会を探します。
通知期間が更新期間を超える契約では、直後の更新も間に合わないことがあります。

残り0〜7日は「7日以内」を優先し、その後「今月中」「来月」「それ以降」と判定します。
ホームの今月・来月は暦月による分類のため、「7日以内」が来月の欄に入る場合があります。
土日には前の平日での申し出を推奨表示しますが、計算上の期限は変更しません。
**祝日・提供元の営業時間は扱いません。**

### 手続きと金額

申し出対象の満了日を保存し、日付が進んでも同じ対象の期限と申し出日を比較します。
期限内の申し出、受付確認、必要な返却が完了すると、対象の満了日で解約済みと判定します。
期限後の申し出は自動完了しません。提供元に確認し、必要に応じて状態を編集します。
すでに解約した契約は、フォームから解約済みとして記録することもできます。

月額×12または年額を年額換算とし、「解約する」とした未解約契約を節約見込みに合算します。
継続中の合計は解約予定・申し出済みを含み、解約済みを除きます。
違約金・返金・日割り・税額の再計算は含まない参考額です。

年表は今月から12暦月を表示し、同じ契約の繰り返し更新も列挙します。
申し出済み・解約済みは年表とホームの手続き対象から除きます。
CSVは一覧では絞り込み・並べ替え後、ホームでは表示した3区分を出力します。
UTF-8 BOM・CRLF・引用符エスケープに対応し、数式として解釈される文字列を無効化します。

## 既存作品との違い

| 作品             | 主な対象・機能                                                     | 本作の焦点                                         |
| ---------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 契約管理システム | 契約書の版管理、承認、監査ログ、PDF、取引先マスタ                  | 自動更新契約の申し出期限の逆算と継続判断           |
| 期限ノート       | 法定点検、車検、資格・免許、保険の満期、リマインド、カレンダー出力 | 間に合う／間に合わないの判定と次の機会、節約見込み |

請求書発行・入金消込は扱いません。
メール・プッシュ通知、外部サービス連携、実際の解約代行、認証、外部API、DBはありません。

## ローカル起動方法

プロジェクト直下で実行します。

```bash
npm install
npm run dev
```

[http://localhost:3000](http://localhost:3000) を開きます。
本番動作の確認：

```bash
npm run build
npm start
```

品質チェック：

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

`npm run lint` は `eslint --max-warnings=0` で警告も検出します。
テストには月末、うるう日、年末、月初のシード分布、4種類の期限、状態境界、
手続きの判定、節約額、CSV、検索・並べ替え、保存データ検証を含みます。

`next.config.ts` の `turbopack.root` は `process.cwd()` のまま使用します。
`cacheComponents`・`partialPrefetching` は使用せず、ルートレイアウトをSuspenseで包みません。

## デモデータについて

- 初回は1件ずつ手書きした14件の架空契約を生成します。
- 日付はすべて開いた日の日本時間から相対的に生成し、保存後は日付を保持します。
- 通常は期限切れ2件、7日以内2件、今月中2件程度、来月3件程度、
  それ以降3件、申し出済み1件、解約済み1件。「解約する」の判断済みは3件です。
- 月末など、7日以内を除く今月中の日付が存在しない場合は、その2例を来月へ繰り越します。
  来月の基本3例は12・18・24日として、7日以内との重複を避けます。
- データはlocalStorageに保存します。保存前の型・範囲・暦日・重複ID・チェックリスト整合性を検証します。
  壊れた保存データは既定データに戻して通知します。保存できない場合も画面に通知します。
- `/about` の「既定データに戻す」で、その日の日本時間を基準に再生成できます。
- すべて架空で、実在の企業・サービス・個人とは無関係です。
- **実際の解約条件は各契約書で確認してください。**
